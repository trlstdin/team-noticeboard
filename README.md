# 一起 · 团队协作告示板

同页五栏告示板、公有账号与拖拽权限分配。前端无依赖，服务端为 Cloudflare Worker + R2。

## 已实现
- 待开发、修复、优化、先接单后开发、已验收五栏；项目统一折叠；事项拖拽跨栏与排序，也可在表单中移动，适合触屏。
- 项目仓库链接、提出者、完成者、栏目说明；左上角切换编辑和只读。
- 公有账号 URL 使用 AES-GCM 加密存储；列表不返回原始 URL，只在服务端授权后复制。
- 按仓库设置只读、编辑者、主管；通过无需登录的专属链接授予权限。
- 账号拖入用户分配，Shift 连选、多选拖拽、全选、给所有人授权、清空授权和单项撤销。
- 编辑、复制、管理三种链接范围分开；链接可撤销；HttpOnly 会话 Cookie。
- 追加式历史、归档保留数据、版本冲突与 R2 条件写防覆盖；公开历史导出。
- 可选将公开变更追加到 GitHub `.noticeboard/events/<uuid>.json`，不提交账号凭据。

## 使用
主管与成员均使用专属授权链接进入。页面不提供第三方登录，不根据第三方登录状态授予权限。密钥不提交到源码。

1. 左上角切换到编辑模式，新建项目并填写组织/仓库 URL。
2. 添加事项，或进入权限管理区添加用户和公有账号。
3. 选择公有账号并拖入用户；Shift 点击连续选择，或使用“分配所选”按钮。
4. 为用户签发链接。复制权限只能访问已经分配的账号，编辑权限还要求用户角色为编辑者或主管。
5. 撤销链接后，原链接及原会话的后续受保护操作都会被拒绝。

## 身份说明与当前限制
本版本使用无需登录的 Token URL。它**不会自动识别 GitHub 组织成员身份**：GitHub Cookie 不可被独立网站读取，需要后续接入可验证的 GitHub 身份服务。主管必须明确授权，匿名访客默认只读。

GitHub Pages 公开前端部署在独立 trlstdin/team-noticeboard 仓库，地址为 https://trlstdin.github.io/team-noticeboard/ 。共享 API 与加密账号存储由 Worker + R2 提供。自动组织成员识别与 GitHub 公开事件镜像仍需要额外接入。

## 环境变量
- `PUBLIC_ORIGIN`：允许的静态前端来源，当前为 `https://trlstdin.github.io`。
- `ADMIN_TOKEN`：总主管 256 位随机入口密钥，仅运行时 secret。
- `DATA_KEY`：账号加密密钥，仅运行时 secret；丢失后无法解密历史账号数据。
- `GITHUB_REPOSITORY`：可选，`owner/repo`。
- `GITHUB_TOKEN`：可选，仅服务端、仅目标仓库 Contents 写权限。

GitHub 同步为保存后的尽力镜像，可由总主管“重试同步到 GitHub”。没有同步成功时，R2 仍是权威来源。仓库权限、网络失败均不会被解释为同步成功。

## 构建与验证
```
npm test
npm run build
```
`dist/server/index.js` 为完整 Worker，`dist/pages/` 为 GitHub Pages 前端。构建为 Pages 注入独立 API 地址；API 只允许配置的 `PUBLIC_ORIGIN` 跨域访问，写操作还需要有效 Bearer Token。Token 仅保存在当前页面内存中，刷新后需重新打开原始链接。Sites 本站访问继续使用 HttpOnly Cookie。

普通公网访客无需登录即可打开 Pages。前端优先读取共享 API；API 暂不可达时，回退到仓库内不含账号凭据的公开只读快照，并标示快照状态。私密账号、Token 哈希及加密历史不提交到公开仓库。

主管可通过管理链接维护用户并签发指向 GitHub Pages 的链接。GitHub Pages 公开前端与受控后台相互独立。

## 历史与边界
R2 日志包含完整追加事件及哈希链。业务操作没有删除历史入口；账号旧密钥以加密事件保留。此设计不阻止云资源所有者直接删除存储或改写 Git 历史，需要通过平台权限与备份进一步约束。清空授权不等于删除账号。

测试覆盖匿名读写隔离、编辑与复制范围、账号加密、跨仓库越权、Token 撤销、并发条件写、历史归档、跨站请求及会话 Cookie。已使用 Chromium 完成五栏显示、新建事项、项目折叠、跨栏拖拽、用户与账号创建、Shift 连选、批量授权、签发链接及移动端权限隔离验证。
