# 一起 · 团队协作告示板

公开网址：https://trlstdin.github.io/team-noticeboard/

以 [DESIGN.md](DESIGN.md) 的 F01—F12 为验收依据。文档按用户最新要求修正：**已有本站授权 Cookie 自动恢复；无 Cookie 且无 Token 时跳转 GitHub 登录；非组织成员只读；Token URL 按明确授权范围进入。**本站不能跨站读取 github.com 的 Cookie。

## 操作
- 有编辑权限时，左上角切换编辑/只读。整张事项卡可以抓起拖动，同栏排序、跨栏移动，边缘自动滚动。手柄只是提示，不是唯一入口。
- 每个项目有独立五栏和整体折叠；已验收另可折叠。新项目、事项默认在前，可拖动项目顺序。
- 栏底说明可直接输入保存。提出者、完成者与仓库地址在事项上展示。
- 主管在同页管理用户、公有账号及其授权。账号整行可拖给用户；Shift 连选、复选、全选、批量授权、清空授权、批量删除分别提供。
- 新签发的特殊链接默认仅复制。编辑与主管链接必须显式授予。删除用户、撤销链接后，旧 Cookie 和旧链接不能继续访问受保护操作。

## 身份与存储
本站 Cookie 保存短期不透明会话标识，服务端检查其来源、权限、过期和撤销；不把客户端填写的用户名或角色当作身份凭据。用户记录关联真实 GitHub 用户资料。无 Cookie 时通过 GitHub OAuth 建立身份，已有 GitHub 登录状态由 GitHub 复用。GitHub API 核对组织成员，非成员不能获得编辑权限。OAuth 部署需要 `GITHUB_CLIENT_ID` 与 `GITHUB_CLIENT_SECRET`；当前变更等待账号所有者完成 GitHub 本人确认后配置后者。

前端托管在 GitHub Pages；共享服务负责权限与加密账号 URL。GitHub Actions 每五分钟将告示快照和独立历史事件写入 `public-state.json` 与 `board-data/events/`。界面明确显示待入库和已提交版本；异步等待不冒充提交成功。事件文件不覆盖、不删除。完整历史可分页查看并全部导出。

公开快照不含账号凭据、用户授权表、Token 或加密私密历史。后台暂不可用时，页面显示快照状态，不假装保存成功。

## 构建与检查
```
npm test
npm run build
```
前端无第三方运行依赖。Node.js 24 构建静态页面和 Worker。`BOARD_SYNC_KEY` 仅在部署环境和 GitHub Actions Secret 中配置，不能提交到仓库。`ADMIN_TOKEN`、`DATA_KEY` 同样只存为运行时 Secret。
