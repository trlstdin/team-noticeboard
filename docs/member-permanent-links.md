# 组织成员永久链接与后台撤权

页面保留用户原文：

> 建议组织成员可以也可以签发组织成员的永久链接。。。。但主管可以后台取消组织成员权限，自然权限和签发权限都可以后台取消

执行用户后续规则：**取消权限直接取消新旧签发。**

- GitHub 验证为组织成员后，可签发绑定自身身份的永久成员链接。链接没有到期时间，持有人可使用成员的告示板编辑和默认账号池权限，不获得主管、权限管理或给他人签发身份的能力。
- 主管在“权限管理”的组织成员区域分别控制成员权限和签发权限。可按真实 GitHub 用户名提前设置禁用，用户未通过成员验证前不能签发。
- 停用成员权限或关闭签发权限，都会撤销该成员已有的成员链接及关联专属链接，并阻止新签发。派生会话逐次检查父链接和成员设置，立即失效；撤销某条链接也使从它继续签发的后续链接失效。
- 恢复权限不会恢复旧链接。成员必须重新签发；仅关闭签发权限时，其本人通过 GitHub 登录仍保留成员工作权限。
- 主管可以逐条撤销成员链接。成员可以撤销绑定自身身份的链接；不能修改主管、其他成员的权限或签发其他成员身份。

成员登记、权限设置与链接摘要仅保存在原私密共享日志，权限变更追加私密审计事件；公开快照不包含成员名册、成员链接或凭据。已有永久主管链接、站点身份、DATA_KEY 和托管配置不变。

本地验证同时覆盖原生和实际解释执行后端，包含组织验证、长期访问、Cookie/派生会话、默认账号池、越权拒绝、新旧签发撤销、恢复后旧链接不复活、父链接撤销传播和并发版本保护。页面检查确认原文提示、成员按钮与主管开关；本会话没有可用的浏览器控制工具，未做浏览器视觉验收。
